# ブラックホール Python 展示版

HTMLではなく、Tkinter + Matplotlib のデスクトップアプリです。
元の geodesic.py を保持し、ray_tracing_3d.py を操作画面付きに改良しました。

## Windowsで起動

ZIPをすべて展開してください。ray_tracing_3d.py だけでは動きません。
既存のプロジェクトに入れる場合は、以前の ray_tracing_3d.py をバックアップし、
同じフォルダに ray_tracing_3d.py / imaging.py / ray_engine.py を置きます。
同梱 geodesic.py は提供いただいた geodesic(9).py と同じ内容です。

PowerShellで展開したフォルダへ移動して実行します。

```powershell
& C:\Users\sun8s\python_test\.venv\Scripts\python.exe -m pip install -r requirements.txt
& C:\Users\sun8s\python_test\.venv\Scripts\python.exe .\ray_tracing_3d.py
```

通常のPython環境なら以下でも起動できます。

```powershell
python -m pip install -r requirements.txt
python ray_tracing_3d.py
```

Tkinterは通常のWindows版Pythonに同梱されています。`No module named tkinter` が
出た場合はPythonインストーラーの変更画面から Tcl/Tk を追加してください。
VS Codeでは通常のPythonファイルとして実行してください（Notebookではありません）。

## 操作

1. b と軌道の向き ψ をスライダーで設定し「光線を発射」。
2. 「3本を比較」で b=4.5, 5.2, 7 を同時に発射。
3. 左の3D図はドラッグで回転。「視点を戻す」で初期位置。
4. 画像の画角・背景の回転・背景の種類・解像度を設定し「像を生成」。
5. 右に「生成された像」、左の奥のスクリーンにも同じ像が表示されます。
6. 生成画像をクリックすると、その画素に対応する光線を3D表示。
7. 「JPGで保存」で保存先とファイル名を選びます。画像本体のみを書き出します。

生成中も光線の発射や3D回転を操作できます。生成はボタンを押した時点の設定です。
設定を変更したら再度「像を生成」を押してください。
b と ψ は1本の選択光線の設定で、画像全体を変える設定ではありません。
画像は画素ごとの異なる b と ψ を計算して構成します。
画像クリック時はスライダー範囲より大きい b が必要になることがあります。
その場合も表示値と光線計算にはクリックした画素の b が使われます。
512画素を選ぶと境界は鮮明になりますが計算時間が増えます。

## 物理・表示の意味

- Schwarzschild時空。G=c=M=E=1、地平面 r=2、光子球 r=3。
- 観測者は r=30 の静止観測者。放射背景は r=120 の球面。
- 各画素から逆向きに光線を追跡し、r=2 に入れば黒、背景球に届けばその色。
- 観測角 α と衝突パラメータは b=30 sin(α)/sqrt(1-2/30)。
- 画像は黒い円の貼り付けではありません。捕獲判定は数値積分によります。
- 同じ b の画素のみ、球対称性を使って積分結果を共有します。
  影の境界をまたぐ補間は行いません。未判定はマゼンタで表示します。
- 奥の平面は画像を見せる展示用スクリーンです。物理的な光線の到達面ではありません。
  光線は球面の背景へ届きます。これは有限の平面に投影される影の計算とは異なります。
- 3D軌道は既存 geodesic.rk4_step を使います。画像生成用 ray_engine は同じ方程式を
  NumPy配列でまとめて積分します。半径に応じた刻み幅で、誤差制御付き積分ではありません。
- アニメーションは各軌道を同じ長さの表示時間に伸縮します。座標時間・固有時間の
  流れを再現するものではありません。矢印方向は観測者からの逆向き追跡です。
- 図はSchwarzschild座標からの座標表示であり、空間の等長埋め込みではありません。
- 自転、降着円盤、放射強度の相対論的補正は扱いません。
- 背景の星は手続き生成した模様です。画像境界付近の高次像には画素化の影響が残ります。
- Matplotlibの3Dは説明用描画です。奥のスクリーンが光線を隠さないよう描画順を固定しており、
  厳密な物体遮蔽を再現する3Dレンダラーではありません。

## ファイル

- ray_tracing_3d.py : 操作画面・アニメーション・JPG保存
- geodesic.py : 元の運動方程式・RK4・2D描画（変更なし）
- imaging.py : 3D軌道、画像生成、背景模様
- ray_engine.py : 画像用のベクトル化RK4
- validate.py : 数値判定・影の半径・JPG出力の再検証
- validation.json : この環境での検証結果
- example_image.jpg : 256×256画素の生成例

`python validate.py` で検証できます。出力例と検証結果は上書きされます。
捕獲/脱出6条件、刻み半減時の判定、影の半径、JPG出力を確認済みです。
3Dの球・光線・スクリーン描画もウィンドウなしの描画環境で確認しました。
Windows/Tkの操作ウィンドウそのものは、この実行環境では未検証です。
